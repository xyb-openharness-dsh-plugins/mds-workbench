## 设计者与研究/场景依据

设计者=小 X 宝家族患者工作台开发者（无人值守夜间窗口）；研究方法与取舍原则见 DESIGNER-BRIEF 与 USER-RESEARCH（0 访谈、0 临床审核如实标注）。用户需求证据与专业约束分开：场景全部 [假设]；医学约束按 CLINICAL-DATA 台账管理。

## 问题、用户与最小闭环

MDS 患者与家属的材料分散在多家机构、以年计的随访里，输血次数、血象变化、疗程进度「记不住、说不清、比不了」。最小闭环：导入/录入 → 核对入档（不判读）→ 趋势与节奏回顾 → 就诊材料导出。输入/动作/输出/失败恢复见 PATIENT-FLOW。

## 功能线（一级导航 7 项）

见 INTERACTION-DESIGN 导航表；差异化线：输血记录（一等实体）、铁监测（只对照）、疗程折叠（32 号）、日常观察（医嘱原话）。每条功能线对应 SCENARIOS S1–S7 与 DIFF-MATRIX D1–D4。

## 方案与 ADR

- A1 布局：业务整页 customFrame + 右侧原生 AI 面板（默认 35%，可拖 25–45%）——选家族 40 号定稿结构；反例：左侧对话（已被家族定稿否决）。
- A2 演示数据：demo 构建器唯一源（build-demo-data.mjs），原型与开发版读同一份 JSON；反例：页面写死数字（L30 教训：原型与生成器分叉）。
- A3 输血为独立实体而非事件备注：节奏聚合、对账、与血象关联都需要结构化字段；反例：塞进自由文本无法聚合。
- A4 风险分层不自动计算：IPSS-R 等只登记医生原话；反例：自算分级=判读列红线。

## 验收与边界

验收=dsh-wb-cli audit 全过 + check 链全绿 + 探针逐条（IP/X/C/MT/A/P/Q）+ 两套档案不串档断言。范围外：移植后管理、多病种冲突核查、任何治疗推荐。

## 数据模型要点

档案（患者/文档）、指标（血象四线+铁蛋白+可比组）、通用 7（输血/用药/疗程/症状记录/医嘱原话/导出/提醒来源）、专属（输血明细、疗程天）、导入 3。字段语境/私密策略/排序在 M3 schema 冻结前定稿（docs/SCHEMA.md）。
